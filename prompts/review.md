# Review: フェーズ／機能実装後の共通コードレビュープロンプト — reifu

> 各フェーズや機能追加の実装が終わったあとに、別エージェントまたは同一ツールの新規セッションへ渡して品質・セキュリティを確認します。

---

## エージェントへの指示

対象フェーズ／機能（例: `docs/specs/NNN_xxx.md`）の実装と差分をレビューし、以下をすべて確認・修正してください。

1. **仕様整合性**: `docs/design/01〜03` および該当する `docs/specs/` の要件・エッジケース・終了コードに漏れや矛盾がないか。
2. **セキュリティ**: パストラバーサル・シンボリックリンク追従・インジェクション（コマンド / TOML / JSONC）・権限過剰・機密露出・境界外値がないか。
3. **実装品質・堅牢性**: ゼロ外部依存の維持、エラー握りつぶしなし、OS / WSL 差異（パス・改行・ロック・権限）、競合状態がないか。
4. **テスト網羅性**: 正常系・異常系・境界値・セキュリティ回帰テストが不足していれば追加する（テスト改ざん・スキップ厳禁）。
5. **知見の還元と引き継ぎ**:
   * 今回判明したドメインルール・設計判断・環境制約があれば `docs/design/` へ簡潔に反映し、正本を最新に保つこと。
   * 該当する `docs/specs/` の受け入れチェックリスト（`- [x]`）を更新し、次フェーズ用プロンプト（`prompts/phases/`）への引き継ぎがあれば追記すること。
6. **最終検証**: `gofmt -s -w .`・`go vet ./...`・`go test -v -race ./...`・`CGO_ENABLED=0 go build ./cmd/reifu` を実行してエラーゼロを確認し、修正内容と残課題（あれば）を簡潔に報告すること。
