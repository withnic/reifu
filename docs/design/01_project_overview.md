# **01\_project\_overview — 霊符（reifu）**

# **1\. プロジェクト概要と目的**

**霊符（reifu）** は、複数の自律型AIコーディングエージェント（Claude Code、Codex CLI、Gemini CLI、Antigravity）を併用する開発者のための、**ローカル完結型AIボイラープレート＆マルチエージェント設定統合CLIツール**である。

## **解決する課題**

1. **プロジェクト立ち上げ時の反復作業の自動化**: 新規リポジトリ作成のたびに `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、各エージェントの設定ファイル、設計ドキュメント雛形（`docs/`）、`.gitignore` を手作業または他者依頼で用意する手間をなくし、コマンド一発で展開する。
2. **「薄いグローバル・自己完結型ローカル」原則の実現**: グローバル設定（`~/.claude/` や `~/.codex/`）に強い禁止ルールや個別権限を溜め込むと、プロジェクトごとに「意図しないブロック」が発生しデバッグが困難になる。霊符はグローバル環境を一切汚さず、すべての規範・権限・フックをプロジェクトローカルに明示的かつ自己完結した形で配置する。
3. **プロジェクトローカルにおける「設定マスター不明（ドリフト）」の解消**: `AGENTS.md`（行動規範の正本）だけでなく、プロジェクト直下の **`.reifu.jsonc`（設定の正本）** を単一ソース（SSOT）とすることで、形式の異なる3エージェントの設定ファイル（`.claude/settings.json`、`.codex/config.toml`、`.gemini/settings.json`）を一元管理する。作業中にClaude Code等で「常に許可」を押して個別ファイルが書き換わった場合も、差分検知（ドリフト検知）と逆取り込み（`reifu sync --import`）により他のエージェントへ即座に横展開できる。
4. **実行環境（Windows / WSL2 / macOS）に応じた自動最適化**: `reifu init` 実行時に OS およびファイルシステム境界（NTFS vs ext4）を自動判別し、最適なリンク方式（ハードリンク / シンボリックリンク / コピーフォールバック）とOS固有のフックコマンドを自動選択する。

# **2\. 全体ワークフロー**

## **2.1 新規プロジェクト立ち上げ（`reifu new` / `reifu init`）**

1. 新規フォルダから立ち上げる場合は `reifu new my-app --preset go-cli`（フォルダ名必須・既存フォルダは拒否）を実行する。既存の空フォルダまたは `git init` 済みディレクトリに導入する場合は `reifu init --preset go-cli` を実行する（`[dir]` 省略時に空でなく `.git` も `.reifu.jsonc` もないディレクトリは `--force` なしでは拒否し、ホームディレクトリ直下は `--force` の有無にかかわらず無条件拒否する）。
2. 霊符が実行環境（`windows` / `wsl2-ext4` / `wsl2-ntfs` / `linux` / `darwin`）を自動判別する。
3. 内蔵テンプレート（またはユーザーカスタムプリセット）を展開し、以下を生成する:
   * `AGENTS.md`（行動規範の正本）＋ `CLAUDE.md` / `GEMINI.md`（ハードリンクまたは環境最適リンク）
   * `.reifu.jsonc`（プロジェクトローカル設定マスター）
   * `.claude/settings.json`、`.codex/config.toml`、`.gemini/settings.json`（`.reifu.jsonc` からコンパイル生成）
   * `.reifu.state.json`（同期状態スナップショット：`.gitignore` に自動追加）
   * `.gitignore`（AI作業用一時ファイル・ロックファイル除外済み）
   * `docs/design/01_project_overview.md` 〜 `03_architecture.md`（全体設計正本雛形）
   * `docs/specs/README.md`（機能仕様書兼チェックリスト保管場所）
   * `prompts/phase0.md` / `add_feature.md` / `review.md`（初回設計・機能追加・共通レビュー用プロンプト）

## **2.2 日常開発と設定ドリフト同期（`reifu status` / `reifu sync`）**

1. 開発者が Claude Code / Codex CLI / Gemini CLI を切り替えながら開発を進める。
2. 対話操作で `.claude/settings.json` に `Bash(go get *)` 等が追記された場合、`reifu status` または `reifu sync` 実行時に `.reifu.state.json` とのハッシュ・管理項目比較により外部変更（DRIFT）を検知する。
3. `reifu sync` はデフォルトで上書きをブロックして警告を表示し、`reifu sync --import` で外部追加された安全な許可ルールを `.reifu.jsonc` へ逆取り込みした上で、他のエージェント設定へ自動展開する。

## **2.3 クローン後のリンク再構築（`reifu link`）**

1. 別環境でリポジトリを `git clone` すると、Git の仕様上 `CLAUDE.md` と `GEMINI.md` は `AGENTS.md` と切り離された独立ファイルとして展開される。
2. `reifu link` を実行することで、`AGENTS.md` を正本として `CLAUDE.md` と `GEMINI.md` のハードリンク（または指定リンク方式）を即座に再構築する。

# **3\. MVPスコープ定義**

# **4\. 非機能要件・セキュリティ原則**

## **4.1 性能と応答性**

* **起動・実行速度**: 全サブコマンドが **50ms 以内** に完了すること（シェルプロンプトやフックからの呼び出しに耐えうる高速性）。※テストでは環境負荷によるフレークを避けるため厳格なミリ秒アサーションは行わない。

## **4.2 安全性・非破壊性・セキュリティ境界**

* **非破壊原則**: 既存ファイルの上書きは `--force` 明示時を除き原則禁止（新規追加または非破壊マージのみ）。
* **アトミック書き込み**: ファイル書き込みはすべて同一ディレクトリ内の一時ファイル経由のアトミックリネーム（`Sync()` 後の `os.Rename`）で行い、途中中断による設定ファイル破損を防止する。
* **管理外フィールドの保持**: 設定ファイル内の霊符管理外フィールド（各ツール固有のUI設定やローカル状態）は削除・破壊せず保持する。
* **プロジェクト境界の厳守**: `links.targets` や設定ファイルの書き込み先について、パストラバーサル（`..`・絶対パス）およびプロジェクト外を指すシンボリックリンク追従を禁止し、グローバル環境や他プロジェクトへの書き込みを完全に遮断する。
* **信頼境界とフック警告**: `.reifu.jsonc` はソースコードと同等の信頼境界として扱う。未信頼リポジトリの初回同期（`STATE_MISSING`）や `hooks.verify_command` 変更時には実行されるフックコマンドを `stderr` に明示警告し、`--no-hooks` でフック反映を抑止できるようにする。
* **逆取り込みガード**: `reifu sync --import` で過度に広範または危険なコマンドパターン（`*`、シェル起動系、`rm -rf *`、`git push *` 等）や `deny_commands` と矛盾するパターンを自動昇格させないガードを設ける。
* **`deny_paths` の位置づけ**: `deny_paths`（`.env` 保護等）はエージェントのファイル操作ツールに対する補助防御であり、Gemini CLI / Codex CLI やシェル経由の読み取りまでは完全には防げないため、機密ファイルは原則ワークスペース外に置く運用を前提とする。

## **4.3 規格・標準化**

* **文字コード・改行コード**: 生成・出力するすべてのテキストファイル（Markdown / JSON / JSONC / TOML）は **UTF-8（BOMなし）・LF（`\n`）** に統一する。
* **シングルバイナリ配布**: `CGO_ENABLED=0` でクロスコンパイル可能な単一バイナリとしてビルドできること。
